# Build a curriculum topic

Read `../add-curriculum-challenge/SKILL.md` for loader paths and completion contracts, then follow `docs/AUTHORING.md`. Use `docs/superpowers/templates/topic-brief.md` for the compact durable brief. Do not load the whole project knowledge file for an ordinary topic.

1. Run `npm run topic:context -- --year N --subject SUBJECT --topic TOPICID`. Read the exact mapping row and referenced statutory text; establish what is outside scope. IDs and category punctuation are permanent once shipped: use the reported paths, never hand-spell them.
2. Plan four slots: supported introduction, reduced support, whole-structure work, application. Choose interactions that teach the requirement; four interchangeable choice screens rarely do. State misconceptions and how each wrong response helps a learner retry.
3. Read the project [visual recipes](../../../docs/VISUAL_RECIPES.md) and inspect the matching built-year game, renderer, illustrated lesson/notes and component test listed by `topic:context`. Preserve that subject's visual teaching approach across all four slots: worked examples, models/diagrams, pictures and manipulatives that support the learning. Specify each slot's representation in the brief. Use [shared recipes](references/challenge-recipes.md) for the relevant interaction, and [English authoring](references/english.md) for English banks. Plain question data alone does not preserve the illustrated experience.
4. Preview `npm run scaffold:topic -- --year N --subject SUBJECT --topic TOPICID --game PATH` to retain the subject's game/visual frame (choose its actual `--topic-prop`, plus `--topic-key` when its internal bank key differs from the curriculum ID). Generic Maths/English scaffolds without `--game` wire shared question visuals and pictured controls, plus an unfinished bank/test and brief; `--builder PATH --export NAME` uses an existing compatible array-returning pure builder instead. Envelopes and custom answer/control models require `--game`. Add `--write` after inspecting paths. Registered topic and statutory mapping are required. These are skeletons; shared visual fallbacks can return null, so inspect their actual output and author any missing model. Never replace bespoke controls or subject answer checking with a generic wrapper.
5. Finish one representative pilot slot and its playthrough before expanding to all four. Keep builders pure (`build(level, rng)`), randomise once per mount and test deterministic seeds. Use shared kinds from `src/data/challenges/questionKinds.js`; extend shared rendering only when an existing kind cannot express the learning.
6. Review all question variants and Bix's four lessons. Each lesson must teach its own challenge in the same representation. Follow the current subject's lesson rollout; where supported add `{ title, lines, example }` entries in `src/data/lessons/<subject>/year<n>/`. Recompute answers independently, reject ambiguous options and tied ordering, check drawing/prompt agreement, and ensure hints narrow the task without giving the answer.
7. Run `npm run check:topic -- --year N --subject SUBJECT --topic TOPICID`. It checks wrappers/imports and supported bank adapters; inspect its limitations rather than interpreting unsupported validation as a pass. Extend bank tests and jsdom playthroughs for wrong-answer retry, hint behaviour where relevant, completion and callback payload. Then run the required full lint, tests and build.
8. Use one batched browser pass only for justified visual/interaction gaps under `AGENTS.md`. Record implementation, technical validation, content review, device review and remaining owner decisions separately. Update the current inventory/architecture references if needed, record delivered outcomes in `docs/CHANGELOG.md` and remove finished backlog work. Keep `PROJECT_KNOWLEDGE.md` short; leave the dated history archive unchanged. Do not call generated or test-passing teaching content approved.

All built curriculum challenges are open regardless of saved completion. Do not add gating, progress writes or year-award participation as part of building content. Read `../curriculum-progress/SKILL.md` before changing these contracts.
