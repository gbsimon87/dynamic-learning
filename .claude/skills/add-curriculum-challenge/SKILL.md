# Adding a Curriculum Challenge

Curriculum challenges are resolved by **file path convention**, not by routing.
Get the path or the filename wrong and the learner silently sees
"⚠️ This challenge is not yet available" — with no build error and no console
clue beyond a failed import. This skill exists to make that impossible.

## Before you write anything

1. **Confirm the topic exists** in the curriculum dataset
   (`src/data/year2MathCurriculum.js` for Year 2 Maths). If the topic isn't in
   that file, the challenge is unreachable — add the topic first.
2. **Derive the topic ID.** It is the topic's `name` run through
   `toKebabCase()` (`src/utils/toKebabCase.js`): lowercase, punctuation
   stripped, spaces → dashes. `"Counting in Steps of 2, 3, 5 and 10"` →
   `counting-in-steps-of-2-3-5-and-10`.
3. **Check which challenges already exist** for that topic, so you build the
   next one rather than overwriting.

## The path convention (exact)

```
src/pages/skills/{subject}/challenges/year{year}/{topicId}/{PascalTopicId}Challenge{n}.jsx
```

`PascalTopicId` is the topic ID with dashes removed and each segment
capitalised — **including numeric segments**, which stay as-is.

| topicId | PascalTopicId |
|---|---|
| `numbers-and-counting` | `NumbersAndCounting` |
| `counting-forwards-and-backwards` | `CountingForwardsAndBackwards` |
| `2-d-shapes` | `2DShapes` |
| `less-than-greater-than-and-equal-to` | `LessThanGreaterThanAndEqualTo` |

Each topic has exactly **4** challenge slots (`n` = 1–4), auto-generated by the
dataset. Co-locate a `.css` file with the identical base name.

> Verify your computed name against the live logic in
> `src/pages/curriculum/Challenge.jsx` (`capitalizeTopicId`) before creating the
> file. Do not trust the table above if that function has changed.

## The component contract

Every challenge component MUST:

- be the **default export**
- accept a single prop: **`onComplete`**
- call `onComplete()` **only** on a correct answer, after a ~1s success delay
- own its own state, its own question randomisation, and its own CSS
- render a `.challenge-container` root and a `.feedback` element

```jsx
import { useState } from "react";
import "./TopicNameChallengeN.css";

function TopicNameChallengeN({ onComplete }) {
  const [feedback, setFeedback] = useState(null);

  const handleSubmit = () => {
    if (isCorrect) {
      setFeedback("✅ Correct! Well done!");
      setTimeout(onComplete, 1000);
    } else {
      setFeedback("❌ Not quite! Try again.");
    }
  };

  return (
    <div className="challenge-container">
      <h3>{/* the instruction, in plain child-friendly language */}</h3>
      {/* interaction */}
      <button className="submit-btn" onClick={handleSubmit}>Submit</button>
      {feedback && <p className="feedback">{feedback}</p>}
    </div>
  );
}

export default TopicNameChallengeN;
```

**Do not** write to `localStorage` from inside a challenge. `ProblemView.jsx`
owns progress persistence; the challenge only reports success.

**Do not** add a route. The dynamic loader finds the file automatically.

## Designing the challenge itself

- **Escalate across the four slots.** Challenge 1 should be the gentlest
  introduction and 4 the most demanding, so a topic reads as a progression
  rather than four interchangeable drills.
- **Vary the interaction.** The existing topics use drag-to-order, fill-in-blank,
  and selection. Four identical multiple-choice screens is a weak topic.
- **Randomise per mount**, so replaying a completed challenge isn't identical.
- **Keep the number ranges age-correct** — check the year group's expectations
  before picking ranges (Year 2 Maths generally works to 100).
- **Instructions must be readable by the target age.** Short sentences, concrete
  words, no meta-language about the app.
- Reuse an existing shared component from `src/components/` when the interaction
  already exists rather than reimplementing it.

## Styling

- Plain CSS in the co-located file. No frameworks, no CSS-in-JS.
- Drive all colours from the CSS variables in `src/index.css` so the challenge
  works in **both light and dark themes**. Verify both before claiming done.
- Touch targets must be large — the audience is 6–8 years old.

## Verify before claiming completion

Do not report success on file creation alone. Confirm:

1. `npm run lint` passes.
2. The dev server loads the challenge at its real URL:
   `/year/{year}/{subject}/problem/{categoryId}/{topicId}/{n}` — reaching it may
   require unlocking prior topics, so seed `localStorage` if needed.
3. A correct answer advances and returns you to `/curriculum`.
4. A wrong answer shows retry feedback and does **not** complete.
5. The challenge is legible in both themes.

## Finally

Update the built-challenges table in §5 of `docs/PROJECT_KNOWLEDGE.md`, and the
relevant row in `docs/PROJECT_IDEAS.md`. A challenge is not done until the docs
reflect it.
